# ACCA F3 — პირადი სასწავლო აპლიკაცია (PWA)

ACCA F3 / Financial Accounting-ის მოსამზადებელი აპლიკაცია ტელეფონისთვის.
მუშაობს **სრულად ინტერნეტის გარეშე**: ყველა ფაილი, PDF და პროგრესი ინახება ტელეფონში (IndexedDB).
სერვერი და გარე API არ გამოიყენება.

მისამართი: **https://shalvakashiashvili-commits.github.io/acca-f3-app/**

შესაძლებლობები: თავების სწავლა და PDF, ქვიზი და ტესტი ფილტრებით, შეცდომების ბანკი, საგამოცდო სიმულაცია, ფლეშქარდები, მეტრო-რეჟიმი (10 წუთი), დაშბორდი (მზადყოფნა, დღიური მიზანი, სერია), სარეზერვო ასლი.

## ლოკალურად გაშვება

```bash
powershell -ExecutionPolicy Bypass -File tools/serve.ps1
```

შემდეგ გახსენი http://localhost:8080/ .
localhost-ზე service worker ჯერ ქსელს მიმართავს, რომ კოდის ცვლილებები მაშინვე ჩანდეს.
სერვერის გამორთვის შემდეგ ფაილები cache-იდან იტვირთება. GitHub Pages-ზე პირიქითაა: ჯერ cache, შემდეგ ქსელი.


## კონტენტის ფორმატი

ერთი JSON ფაილი = ერთი თავი (`chapter`, `summary`, `case_study`, `flashcards`, `questions`).
დამატებითი კითხვების ფაილს საკმარისია ჰქონდეს `{ "chapter": { "id": N }, "questions": [...] }`.
კითხვები ერწყმის `id`-ით. ხელახალი იმპორტი პროგრესს არ შლის.

არასავალდებულო ველები, რომლებიც სქემას დაემატა:
- `chapter.weight` — თავის წონა გამოცდის სიმულაციაში. თუ არ არის მითითებული, წონა თავის კითხვების რაოდენობის პროპორციულია.
- `tolerance` (numeric კითხვაზე) — დასაშვები ცდომილება (ნაგულისხმევად ±0.5).
- `difficulty` — 1-დან 5-მდე.

## ქულები და შეცდომების ბანკი

- კითხვა ან mtq-ის ნაწილი ფასდება ან სრული ქულით, ან 0-ით. `multi`-ზე ქულა მხოლოდ ყველა სწორი ვარიანტის მონიშვნით მოდის.
- mtq-ის ქულა = სწორი ნაწილების ჯამი. თუ ქულა სრული არ არის, კითხვა ბანკში შედის.
- `numeric`: ინტერვალი, მძიმე და `$ £ € ₾` იგნორირდება; `(500)` = −500.
- ტესტში უპასუხო კითხვა = 0 ქულა და შედის ბანკში.
- ბანკიდან გასასვლელად საჭიროა 3 ზედიზედ სწორი პასუხი, რომელთა შორის სულ მცირე 2 სხვადასხვა დღეა. შეცდომა სერიას ანულებს.
- ყოველ ქვიზსა და ტესტში არჩეული თავებისა და წყაროს შეცდომები შეადგენს სულ მცირე 30%-ს (იცვლება პარამეტრებში). შეცდომა შეირჩევა წონით, სადაც წონა = შეცდომების რაოდენობა.
- თარიღის სიმულაცია ტესტირებისთვის (კონსოლში): `(await import('./js/core/clock.js')).shiftDays(1)`

## საგამოცდო სიმულაცია

- **ვარიანტები:** სრული (35 კითხვა × 2 + 2 mtq × 15, 2 საათი) და მინი (ნახევარი: 17 + 1 mtq, 1 საათი). ფორმატი და ჩაბარების ზღვარი (50%) იცვლება პარამეტრებში.
- **წყარო:** აპლიკაცია / კრებული / ორივე.
- **სექციები:** Section A = ყველა ტიპი, გარდა mtq; Section B = mtq. ქულა კითხვაზე = (მიღებული / მაქსიმუმი) × სექციის ქულა.
- **შერჩევა:** კითხვები ყველა თავიდან, `chapter.weight`-ის პროპორციულად. წონის გარეშე თავს კითხვების რაოდენობის პროპორციული წილი ხვდება. თუ წონა მხოლოდ ზოგ თავს აქვს, დანარჩენები მითითებული წონების საშუალოს იღებენ.
- **თუ კითხვები არ ჰყოფნის:** ჩანს, რამდენი აკლია. გამოცდა შეიძლება ჩატარდეს არსებული კითხვებით. ქულა მაინც 100-დან ითვლება, დრო კი მცირდება შესაძლო ქულის პროპორციულად.
- **ტაიმერი:**
  - ნაგულისხმევად ჩერდება, როცა გამოცდის ეკრანს ტოვებ; შედეგში ჩანს პაუზების რაოდენობა და ხანგრძლივობა.
  - „მკაცრი რეჟიმი“ (პარამეტრებში): დრო ითვლება დაწყებიდან.
  - ბოლო 10 წუთზე გაფრთხილება. 0-ზე გამოცდა ავტომატურად სრულდება, აპლიკაციის გახსნისას — ასევე.
- **გამოცდის დროს** სწორი პასუხები და ახსნები არ ჩანს. არასწორი და უპასუხო კითხვები შედის შეცდომების ბანკში.
- **ტესტირება:** დროის გადაწევა კონსოლში — `(await import('./js/core/clock.js')).shiftMs(10*60000)`.


## ფლეშქარდები, მეტრო-რეჟიმი, დაშბორდი

- **ფლეშქარდები** (`#/cards`, „ვარჯიშის“ ეკრანიდან ან თავის ეკრანიდან):
  - რისგან: თავის `flashcards` + `summary.must_memorize`.
  - „არ ვიცი“ — ბარათი წყების ბოლოს კიდევ ერთხელ გამოჩნდება.
  - „ვიცი“ — შემდეგი ჩვენება 1, 3, 7, 14, 30 დღეში (Leitner).
  - პროგრესი ხელახალ იმპორტს უძლებს (ბარათის id = თავი + ტექსტის ჰეში).
- **მეტრო-რეჟიმი** (ღილაკი მთავარ ეკრანზე):
  - 10 წუთი, კითხვები და ბარათები შერეულად. კითხვები შეცდომების ბანკიდანაა (წონით); თუ შეცდომა 6-ზე ნაკლებია, ემატება ახალი ან სუსტი კითხვები.
  - mtq არ შედის, რადგან 10 წუთში არ ეტევა.
  - დრო ჩერდება ეკრანიდან გასვლისას. სესია შეწყვეტის შემდეგ იმავე ადგილიდან გრძელდება.
- **მზადყოფნა** = 0.6 × თავების ქულა + 0.4 × ბოლო 3 გამოცდის საშუალო − ჯარიმა:
  - თავების ქულა = თავების დაფარვის საშუალო, თავის წონით. დაფარვა = ბოლო შედეგების ჯამი / თავის ყველა კითხვა.
  - ჯარიმა = (ბანკში მყოფი შეცდომები / ყველა კითხვა) × 100 × 0.5, მაქსიმუმ 15.
- **დღიური მიზანი**: ნაპასუხები კითხვები და ნანახი ფლეშქარდები დღეში (ნაგულისხმევად 20, იცვლება პარამეტრებში). **სერია** = ზედიზედ დღეები, როცა მიზანი შესრულდა.

## სარეზერვო ასლი და მეხსიერება

- **ექსპორტი** (პარამეტრები → სარეზერვო ასლი):
  - შედის: თავების JSON კონტენტი, პროგრესი, შეცდომების ბანკი, ქვიზების, ტესტებისა და გამოცდების ისტორია, ფლეშქარდები, სანიშნეები და შენიშვნები, პარამეტრები.
  - PDF-ები მხოლოდ მაშინ შედის, თუ „PDF ფაილებიც“ მონიშნულია.
  - ფაილის სახელი: `acca-f3-backup-YYYY-MM-DD.json`.
  - ტელეფონზე „გაზიარება / ფაილებში შენახვა“ ფაილს Files-ში, Google Drive-ში და სხვაგან ინახავს.
- **აღდგენა** = სრული ჩანაცვლება ფაილიდან:
  - თუ ფაილში PDF-ები არ არის, ტელეფონზე არსებული PDF-ები რჩება.
  - ერთ ტრანზაქციაში სრულდება: ან ყველაფერი აღდგება, ან არაფერი.
- **შეხსენება**: თუ 7 დღეზე მეტია ექსპორტი არ გაგიკეთებია, შეხსენება მთავარ ეკრანზე ჩნდება.
- **მუდმივი მეხსიერება**: აპლიკაცია ითხოვს `navigator.storage.persist()`-ს, რომ ტელეფონმა მონაცემები თვითონ არ წაშალოს. სტატუსი ჩანს პარამეტრებში.
  - Android/Chrome ჩვეულებრივ ადასტურებს, თუ აპლიკაცია მთავარ ეკრანზეა დაყენებული.
  - iPhone-ზე მონაცემები უფრო საიმედოდ ინახება მთავარ ეკრანზე დაყენებული აპლიკაციისთვის. სარეზერვო ასლი მაინც აუცილებელია.

## ტელეფონზე დაყენება

მისამართი: https://shalvakashiashvili-commits.github.io/acca-f3-app/

**iPhone (Safari):**
1. გახსენი მისამართი **Safari**-ში. Chrome-იდან iPhone-ზე მხოლოდ iOS 16.4+-ზე გამოდის.
2. ქვედა ზოლში დააჭირე **გაზიარების** ღილაკს (კვადრატი ისრით ზემოთ).
3. ჩამოსქროლე და აირჩიე **„Add to Home Screen“ / „მთავარ ეკრანზე დამატება“** → **Add**.
4. გახსენი აპლიკაცია მთავარი ეკრანის ხატულიდან და დაელოდე 10–20 წამი ინტერნეტით, სანამ ყველა ფაილი ჩაიტვირთება. პარამეტრებში უნდა ეწეროს „✅ აპლიკაცია მზადაა offline მუშაობისთვის“.

**Android (Chrome):**
1. გახსენი მისამართი **Chrome**-ში.
2. ⋮ მენიუ (ზედა მარჯვენა კუთხე) → **„Install app“ / „აპლიკაციის დაყენება“**. თუ ეს არ ჩანს, აირჩიე **„Add to Home screen“**.
3. დაადასტურე **Install**.
4. გახსენი ხატულიდან და შეამოწმე პარამეტრებში offline სტატუსი.

ამის შემდეგ ინტერნეტი აღარ არის საჭირო: PDF-ები და JSON ფაილები აპლიკაციის ბიბლიოთეკაში ტელეფონიდან იტვირთება.
⚠ მონაცემები ინახება **იმ ბრაუზერში / იმ აპლიკაციაში**, საიდანაც ატვირთე. Safari-ს ჩანართი და მთავარ ეკრანზე დაყენებული აპლიკაცია iPhone-ზე სხვადასხვა მეხსიერებას იყენებს. ამიტომ ფაილები ატვირთე დაყენებულ აპლიკაციაში.

## მომავალი ცვლილებები: როგორ შევიტანო

**კონტენტი (თავები, კითხვები, PDF)** კოდში არ ინახება და GitHub-ზე არ იტვირთება. ის ტელეფონიდან, აპლიკაციის ბიბლიოთეკაში ემატება. კოდის შეცვლა არ სჭირდება.

**კოდი (დიზაინი, ფუნქციები):**
1. შეცვალე ფაილები ამ საქაღალდეში. ინტერფეისის ტექსტები `js/strings.ka.js`-შია.
2. შეამოწმე ლოკალურად (`tools/serve.ps1`, შემდეგ http://localhost:8080/).
3. ახალი ფაილი ჩაწერე `sw.js`-ის `ASSETS` სიაში.
4. **გაზარდე ვერსია** ორ ადგილას: `VERSION` `sw.js`-ში (მაგ. `v1.0.1`) და `APP_VERSION` `js/config.js`-ში. ამის გარეშე ტელეფონი ძველ ვერსიას დაიტოვებს.
5. ატვირთე GitHub-ზე:
   ```powershell
   git add -A
   git commit -m "მოკლე აღწერა"
   git push
   ```
6. GitHub Pages საიტს 1–2 წუთში განაახლებს (Actions ჩანართში ჩანს „pages build and deployment“).

**როგორ განახლდება ტელეფონზე:**
1. გახსენი აპლიკაცია ინტერნეტით. service worker ახალ ვერსიას ფონურად ჩამოტვირთავს.
2. ჩნდება შეტყობინება **„ხელმისაწვდომია ახალი ვერსია“**. დააჭირე **„განახლება“**.
3. თუ შეტყობინება არ ჩანს: დახურე აპლიკაცია მთლიანად (აპლიკაციების გადამრთველიდან) და გახსენი თავიდან.
4. ვერსია ჩანს პარამეტრების ბოლოში.

პროგრესი, PDF-ები და კონტენტი განახლებისას **არ იშლება**, რადგან ისინი IndexedDB-შია და არა cache-ში. თუ ბაზის სქემა იცვლება, `db.js`-ში `DB_VERSION` იზრდება და ემატება `if (old < N)` ბლოკი, რომელიც არსებულ მონაცემებს გადაიყვანს ახალ სქემაზე.
